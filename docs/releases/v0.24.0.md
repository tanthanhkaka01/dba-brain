## Summary

**One set of rules, written down, each held by a test.** The rules dbabrain keeps are one numbered
list, [`docs/rules.md`](../rules.md): who may import, run or reach whom, what a `common.cli` command
takes and answers, how configuration is read. Every rule names the test that fails when it is
broken. This release is mostly the work of making the code keep them - which is what lets the next
feature go in one obvious place.

**`common.cli` reads no configuration.** A command that does a job - run SQL, run a command on a
host, restore a backup, kill a session - takes everything it needs in its request and runs the same
on a machine with nothing configured. The apps (the bot, the SQL tasks, backup and restore, `sre`)
fill the request from their own `data/` before they call, and send it on stdin because it carries a
password. A command whose job *is* the configuration - registering a task, storing a secret,
checking the reference - still reads and writes it. **A script that sent `common.cli` only a
`server_id` must now send the login** (see *Changed*).

**One command per job.** Where two commands did the same thing, one stays and the other went:
the inventory summary is `common.cli inventory-summary`, the inventory workflow `reports.cli
inventory-workflow`, this node's clock `db.cli timezone`, this node's status `common.cli
self-status`, verifying a restore `common.cli verify-restore`. `upgrade-config` points a configured
command line at the one that stays.

**A SQL Server RESTORE is written in one place.** The nightly SMB restore and the container drills
now apply every file - full, differential, each log, the point-in-time `STOPAT` - through the same
`common.cli restore-full` / `restore-diff` / `restore-log`. The statements the SMB restore sends are
the ones it sent before, byte for byte.

**No app reaches a host by itself.** Shares, remote commands, file copies and `sqlcmd` all go
through `common.cli`: `smbclient` and `cmdkey` are `smb-list` / `smb-get` / `smb-delete` /
`smb-credential`, SSH and WinRM are `run-cmd`, `push-file` and `pull-file`.

## Added

- **`docs/rules.md`** - the rules, numbered R01-R43, each with its guard test; and
  `tests/test_every_rule_names_a_guard_that_exists.py`, which fails if a rule names a test that is
  not there.
- **`smb-list`, `smb-get`, `smb-delete`, `smb-credential`** - a Windows share, reached the same way
  from a Linux node (`smbclient`) and a Windows one (the UNC path after `cmdkey`). Stdin only.
- **`restore-full` / `restore-diff` / `restore-log` take `move_files`** (the data and log paths; the
  logical names are read on the server) **and `sqlcmd`** (run where the SQL Server is, one file per
  call, answered as `run-sqlcmd` answers).
- **`common.cli self-status` takes `last_runs`** - each app command's newest run, stated by the
  caller; `/spbot_self_status` fills it from the node's store.
- **`db.cli timezone --format txt`**, and it answers without opening the store unless asked to
  `--record` or `--list`, and with no readable `config.json`.
- **`upgrade-config` step `moved-commands`** - points a configured command line at the CLI a
  command moved to.
- **`db.cli archive-keys`** - reports, and with `--apply` adds, the primary keys the two archive
  tables now have.

## Changed

- **Every `common.cli` operation takes its login in the request** - **breaking** for a script that
  sent only a `server_id`. `run-sql`, the emergency commands, the catalogue listings, `db-status`,
  `trace-session`, `copy-schema` and the patch and instance commands take `"connection"` (the SQL
  login, complete: `db_type`, `host`, `port`, `username`, `password`); `run-cmd`, the file transfers
  and the host commands take `"access"` (the host's `cmd_access` with its password or key file);
  `probe-host` takes `"host"`. A key named by its bare file name is refused - give its full path -
  and a `password_ref` must be in the request's `"secrets"` or the environment. The bot, the SQL
  tasks and backup/restore do this for you; from a shell, write the request to a file and pass
  `@file`.
- **Removed, each for the command that does the same job**: `control inventory-summary` and
  `inventory-workflow`, `common.cli timezone`, `db.cli self-status`, `backup_restore.cli
  verify-restore`, `common.cli restore-database`, `backup_restore`'s hidden `restore-full` /
  `restore-diff` / `restore-log`, and `restore-by-id` for an SMB entry (use `restore-workflow
  --restore-id <id>`, latest or `--point-in-time`).
- **A point-in-time `STOPAT` is written `YYYY-MM-DDTHH:MM:SS`** for every restore - the form SQL
  Server reads the same under any login language.
- **`db-ops init`, `guide`, `encrypt-secret`, `export-data`, `import-data` and `check-credentials`
  take one JSON object**; an old flag is refused with the key it became.
- **Metric collection runs through `common.cli metric-batch`**, one process per target; `sre` runs
  through `run-cmd` and needs the `ssh` extra.
- **`APP-BACKUP-RESTORE` runs every second by default**, so restores due together run together up
  to `max_parallel`.
- **`force-hourly-report` reports the stored results** and collects nothing.

The full list, with what to do for each, is in [`CHANGELOG.md`](../../CHANGELOG.md).

## Fixed

- **`run-sql` answered a traceback instead of JSON when its target dropped mid-statement.**
- **A quote in a database name or path broke the SMB restore's full-restore batch** - it is escaped
  for each literal it sits in.
- **`/spbot_self_status` said "last run unknown"** on a node upgraded from before 0.23.0.
- **An Oracle SQL task with `parameters` runs on a direct connection, and a PostgreSQL task can have
  parameters** - bound by name, `:name` in the script.
- **`run-sql`'s `major_version` decides the driver again** when the login comes as `connection`.
- **`sre ... --dry-run` printed the MySQL admin password.**

## Known limitations

- **The Windows paths of the SMB restore and the share commands are proven offline only** - the
  UNC share, the WinRM certificate import and the share cleanup had no Windows target to run
  against. The Linux paths ran on the release drill.
- **An existing store keeps its archive tables without keys** until `db.cli archive-keys --apply`
  is run; on a large store it reads every archived row.
- **A point in time with an offset is converted to UTC**, the clock of every container target. For
  a server whose clock is not UTC, give the moment without an offset, in that server's own clock.
- **A PC node has no supervisor.** Run a daemon started by hand under a service manager.

## Upgrading

`SCHEMA_VERSION` is unchanged, so the store needs nothing (the archive keys are optional, above).

```bash
pip install --upgrade dbabrain
python -m db_ops.common.cli upgrade-config '{}'                   # read the plan
python -m db_ops.common.cli upgrade-config '{"dry_run": false}'   # then apply it
```

**If a script of yours calls `common.cli` with a `server_id`**, give it the login instead, or call
it through the app that owns the configuration. **If it calls a removed command**, the *Changed*
list above names the one that does the same job.
