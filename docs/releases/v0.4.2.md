## What this release is for

Adds a scan that detects secret-store values in outgoing files, and removes deployment-specific
values from shipped defaults. No action is required for existing installations.

## Added since v0.4.1

- **`db-ops common check-secret-literals`** — scans files for literal values held in your secret
  store. The store is decrypted and its values are matched exactly; a finding reports the ref, the
  file and the line, and never the value. A passphrase is required, supplied by `--key`,
  `--key-base64` or `DB_OPS_SECRET_KEY`; without one the command exits with an error rather than
  reporting a result. Covered by `tests/test_secret_literals.py`.

- **`tests/test_worker_host_is_not_hardcoded.py`** — asserts that no host address appears in a
  shipped command's arguments or in a result link.

## Fixed since v0.4.1

- **`spbot_create_db_docker` and `spbot_report_inventory` contained a hard-coded worker address.**
  Both now resolve `{worker_host}` from `config.json`, and render it empty when no worker is
  configured. An existing `data/telegram_support_commands.json` is not modified; the change applies
  to the catalogue written by `db-ops init`.

- **`check-identifiers` did not match names of the form `<name>_<octet>_<octet>`**, because `_` was
  treated as a word boundary. The boundary now excludes an adjacent digit, and a separator followed
  by a digit, so it matches names joined by `_` or `-` without matching inside an address or a
  version number.

- **`data/telegram_groups.example.json` now ships placeholder group ids and titles.**

## Changed / breaking

- No breaking changes. Every change applies to files written by `db-ops init`; existing
  configuration is left as it is.

The identifier boundary was tested against ten inputs in both directions, including an address
written with hyphens and a version number, which must not match, and a name joined by underscores
and a bare two-octet reference, which must.

## Known not to work

- `copy-schema` is covered by offline tests only. It has not been run against two live SQL Server
  instances.
- Backup/restore, the inventory workflow and the SRE app are documented but have not been executed
  end to end.
- Supported and tested on Python 3.12 and 3.13 only.
