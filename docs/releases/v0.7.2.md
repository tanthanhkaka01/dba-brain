## What this release is for

The release before this one shipped with a real machine name inside it, and the check that exists
to prevent exactly that reported the tree as clean. The obvious response is to add the name to a
list. That would have been the fourth time, so the question asked instead was *why does a scan that
derives its terms from the inventory keep missing things* — and the answer was not one bug.

Between knowing a term and reporting it there were four filters, each of which quietly dropped
something real. This release closes all four and scrubs what had already crossed. If you publish
anything from this toolkit, this is the release to be on.

## Fixed since v0.7.1

- **A composite value was searched for only as a whole.** `server_name` is stored as
  `HOST\INSTANCE`, and that pair was the only spelling the scan knew — so a comment naming the
  machine on its own matched nothing. The same shortfall already had a rule for addresses ("prose
  does not repeat a whole address"); it had never been generalised from addresses to names.
  `_harvest` now adds the parts beside the whole, and refuses to split an address into octets or to
  make a search term out of a bare port. On one estate this taught the scan five hostnames it had
  never known.

- **The `review` tier was hidden, not just un-refused.** It is excluded from `hits` deliberately —
  a gate that refuses over the word "inventory" is a gate people route around — but it was left out
  of the printed report as well, so a database name could be matched and never seen by anyone. It
  now prints, with the files, and still does not refuse.

- **`unrecognised_addresses` was collected and never printed**, though the module's own docstring
  calls it the one category an inventory-derived scan is structurally unable to find. Same
  treatment: it prints, so a person can confirm each one is a placeholder.

- **`SKIP_DIRS` was matched against the absolute path.** Scanning a tree that merely lives under a
  directory called `build`, `dist`, `deploy` or `runtime` therefore opened no file at all — and
  zero files produce zero hits, which reads as clean. The skip list is now relative to the root,
  and **a scan that opens no file refuses**, the same rule the module already applied to having no
  terms, for the reason it states: the one failure this checker must never have is the one it would
  report as success.

- **What had already crossed was scrubbed**: a machine name in a shipped collector comment, in
  three tests and in one component doc; two database names used as sample rows; and an estate's
  routed subnets used as network fixtures — moved off those ranges while staying inside Docker's
  default pool, because that containment is what those tests assert. The scanner's own comment no
  longer names real databases to explain why its tiers exist.

## Known not to work

- **The scan matches literals, not subnets.** An address in the same subnet as a configured one is
  not a hit; it appears in the unrecognised-addresses list, which is now printed but still needs a
  person to read it.

- **A broken WinRM transport is still recorded as a metric warning** (carried over from v0.7.1).
