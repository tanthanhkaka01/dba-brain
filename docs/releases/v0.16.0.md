## What this release is for

Two things, from two different readers.

The first opened a published index-usage page and could not act on it. It said `Fragmented (227)`
and listed the same index name fourteen times at fourteen percentages — which turned out to be
**partitions**, not duplicates, and the page had no column that could say so. It also linked "Fleet
inventory" at a machine that had been retired two days earlier, because the base URL those links
are built from is one configured string and nothing re-renders a page already on disk.

The second was a person reading `/spbot_self_status` on a phone, who had every fact about the
process and no way to reach anything it had produced.

## Added since v0.14.0

- **A showcase of real published pages ships with the release.** `examples/showcase/` holds the four
  report families an estate actually publishes — fleet inventory, server metrics, per-server index
  usage, SLA — with every name that belongs to that estate replaced by a stable fake one, and
  `examples/` now ships whole: to the public repository and, via `MANIFEST.in`, to the PyPI sdist.
  There is a GitHub Pages workflow beside it, because no HTML in a repository is viewable by
  clicking it and the fleet metrics page fetches its data per server.
- **The head banner links the per-server index report.** It offered three pages and never that
  family, so an estate could publish one per server every night with nothing pointing at any of
  them.

- **A head banner on every published page** (`db_ops/lib/page_banner.py`) — product, page title,
  scope, and `snapshot <time>` in the configured timezone. `index-usage_<server>.html` had no head
  at all; the other three pages each answered "how old is this" in a different wording. The stamp is
  the moment the numbers were **measured**, so a page rebuilt for a past day says that day.
- **The console links to the reports.** `/db_ops/` gains a *Reports* group naming the fleet
  inventory, server metrics and the SLA page. They were two mounts on one listener with nothing
  joining them, so a signed-in user could not reach a report without being told the URL. The mount
  comes from the server that is actually serving it, never from a second config key.
- **`self-status` lists this installation's own web addresses**, built from the node's own address
  and the webhost command's own `--port` — and **warns when `report_base_url` names a different
  host**, which is the check that would have caught the stale links on day one.
- **`build-showcase`** — copies the published pages into a folder with every identifier this estate
  owns replaced by a stable, shaped fake, so real pages can be shown to people who must not learn
  anything about the estate. Terms come from `check-identifiers`' inventory-derived list and from
  db_ops's own output shapes, never from a guess; the result is handed back to that same scanner and
  **any finding deletes the output**.

## Fixed since v0.14.0

- **A registered instance now reaches the fleet inventory report.** The canonical
  `database-inventory.json` was seeded once and the health overlay only updated servers it already
  listed, so nothing registered afterwards could appear — measured on a node whose canonical file
  held 1 server while the register held 43. Every run now adopts what is missing: add-only,
  idempotent, and gated by the flags the register already cascades
  (`enabled` → `metrics` → `reports` → `alerts`). **On upgrade:** a machine you deleted from the
  canonical file by hand will come back if it is still registered and enabled; say it with
  `reports: {"enabled": false}` on the instance instead, which also keeps it collected.
- **`build-showcase` produces pages that render.** It copied only the HTML, so every chart on the
  fleet page was empty; it rewrote the page's own stylesheet, its JSON keys and its template
  literals, so pages arrived unstyled or dead; and it left schema, table, index and
  stored-procedure names untouched because it only read one of the two shapes a page writes them
  in. The data files a page fetches are now copied and scrubbed with it, the code that renders a
  page is never rewritten, and pages are named after the moment they state, in UTC.
- **`check-identifiers` stops reporting measurements as machines.** Its two-octet shorthand tier
  read `"sharePct": 0.2` and `version: 2.53.1.0` as references to a host; it now requires the
  shorthand to touch a name, which is the form the tier was bought by. A request's `allow` list
  now also applies to the address backstop, which is the one tier that most needs it.

- **Fragmented index rows are actionable.** One row per **partition**, identified as such
  (`#p<n>`, and only where the index has more than one), with `page_count`, `size_mb`,
  `index_type`, the schema and `STATS_DATE`. The summary carries `distinct_indexes` and `total_mb`,
  because "157 fragmented indexes" and "157 fragmented partitions of 22 indexes" are different
  findings and only the second one was true.
- **The page no longer contradicts the collector that measured the row.** It recomputed the action
  at `>= 30% = REBUILD` while the collector calls `>= 60%` REBUILD — so every row between 30 and 59
  rendered as the opposite of what the tool decided.
- **The worst index is listed first.** The table sorted on the *string*, which put `100.0` below
  `99.9`; the single worst index on an instance sorted to the bottom and was the first row a capped
  table dropped.
- **Published pages link relatively.** The report text keeps absolute URLs, because half its
  audience reads it in Telegram; the rendered page gets the relative form, which resolves against
  whatever host served it. A link to another host is left exactly as it is.
- **No estate branding on a shipped page.** `ORG / TRX` was literal markup in the inventory
  template and the server template drew its eyebrow from the estate's own `company` field.

## Changed / breaking

- **A server you deleted from `database-inventory.json` by hand comes back** if it is still
  registered and enabled. That file is seeded once and the health overlay only updated servers it
  already listed, so anything registered afterwards never reached the fleet page — collected,
  alerted on, given its own index report, and invisible. Adoption fixes that and costs this: the
  canonical file no longer records a deletion. **Say it in the register instead** —
  `reports: {"enabled": false}` on the instance keeps it collected and off the page, `enabled: false`
  stops both. Nothing is ever removed from the canonical file by this release.
- **`examples/` now ships with the distribution**, to the public repository and to the PyPI sdist
  (`MANIFEST.in`). The sdist grows accordingly — 99 example files, 61 of them showcase pages.
- **`check-identifiers` reports fewer false positives.** Its two-octet shorthand tier now requires
  the shorthand to touch a name, so `"sharePct": 0.2` and `version: 2.53.1.0` are no longer read as
  references to a host. If you depended on the old noise, you will see less of it.

## Known not to work

- **Nothing asserts the four-way default.** Adding an instance defaults to on for the fleet
  inventory, its per-server metric page, the index report and SLA — that is true in this release and
  was measured on the node — but no test holds the property, so the four mechanisms behind it can
  drift apart again. A guard was started during the soak and dropped on purpose: R4 makes a code
  change a new artifact and a new clock. It is 0.17.0's first job.
- **No `backup-add` / `restore-add`.** Registering a backup or a restore is still a hand-edit of
  `data/restore_config.json` — the same complaint that produced `instance-add`, deferred for the
  same reason as the item above.

Everything deferred out of this release is written up in
[`audits/TEST_VERSION_BEFORE_RELEASE_DETAIL_0_17_0.md`](../../audits/TEST_VERSION_BEFORE_RELEASE_DETAIL_0_17_0.md).
- **A new SQL Server target has no index page for up to a day.** `MAINTENANCE_INDEX_USAGE` is
  windowed to `from_hour: 1, to_hour: 6` with a 20-hour repeat, because it is one of the heavy ones.
- **Index usage is SQL Server only**, and a target with `disabled_collector_types: ["sql"]` — an FCI
  passive node, say — correctly has none.
- **The showcase in `examples/` is a snapshot, not a live view.** The fleet page there cannot answer
  `?date=`, because that is the web host reading its archive and a folder of files has no host.
- **`db-ops --version` prints the internal image counter**, not the released number. The released
  number is the distribution's own metadata (`pip show dbabrain`) and `PUBLIC_VERSION`.
